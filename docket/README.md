# Docket E comparator

The first Exec acceptance trial's tool (DEC-251, item E of the Convention synthesis; handoff
HO-ANA-20261117-2VK1 in the private coordination records). For each request it asks one question: did
the reply that came back get filed, once, unchanged, and is the filing the original rather than a later
reconstruction?

```
python3 -m docket.comparator docket/cases/synthetic-v1/manifest.json \
    --gold docket/cases/synthetic-v1/gold.json --code-version "$(git rev-parse HEAD)" -o report.json
```

Exit 0: report written, no stop. Exit 2: a stop condition (ungranted input, ambiguous normalization,
unimplemented normalization version). Exit 3: a wrong gold classification. Any stop means re-pin before
running again.

## What is pinned

- **Code:** the commit passed as `--code-version`, recorded in the report.
- **Normalization:** `docket-norm/1` (NFC, line endings, trailing spaces, outer blank lines). Nothing
  else is forgiven: case, inner whitespace, quoting and punctuation are differences. A pair equal only
  under a looser rule stops the run.
- **Inputs:** `manifest.json` lists every file the comparator may read, with its sha256. Nothing else is
  read. A file whose bytes don't match is `unknown`, never `missing`. The report carries the manifest's
  digest.
- **Window:** fixed in the manifest before any observation: two eligible scheduled consumer wakes and a
  24-hour wall cap.

## What it does not do

It doesn't observe consumer uptake. Acceptance needs a named recipient's ACK plus a row-specific
disposition, checked by someone who is neither producer nor consumer; a report file, an ACK or copied
text alone counts as zero. It doesn't validate Anamnesis retrieval, Prospero, Fathom or MtG. Stage A uses
only the synthetic set in `cases/` (written for this repository, regenerated by `docket/synthetic.py`);
a later stage reads only explicitly permitted, pinned repository snapshots through the same manifest.
The trial's planted discrepancy is chosen by someone other than the producer.
